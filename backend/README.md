Backend bootstrap (skeleton)

This repo currently contains only docs. This folder introduces the backend structure and the initial Prisma schema for the User model.

What was added:
- prisma/schema.prisma defining the users table with:
  - id (UUID), email (unique), password_hash, salt (nullable), status, verification_token (nullable), verification_expires_at (nullable), created_at, updated_at
  - indexes on status, created_at, verification_token
- src/modules/user/domain/entities/User.ts domain entity
- src/modules/user/repository/UserRepository.ts repository interface and stub
- src/core/security/passwordHasher.ts hashing interface and placeholder implementation
- src/modules/user/domain/services/UserService.ts basic service with register() and getByEmail()

Notes:
- Sensitive fields must never be logged (passwordHash, salt, verificationToken).
- Prisma datasource expects DATABASE_URL env var pointing to PostgreSQL.
- Migrations will be generated by Prisma Migrate once tooling is wired (package.json, dev dependencies).

Security services added:
- ScryptPasswordHasher using Node crypto with env-configurable work factors (SCRYPT_N, SCRYPT_r, SCRYPT_p, SCRYPT_KEYLEN)
- validation utilities for email normalization/validation and password policy enforcement
- high-level helpers: hashPassword(), verifyPassword()
- UserService now validates email and password strength before hashing

HTTP API added:
- Express server in src/server.ts
- Auth routes in src/modules/user/interfaces/http/authRoutes.ts (signup)
- Login route in src/modules/auth/interfaces/http/loginRoute.ts
- Refresh + logout routes in src/modules/auth/interfaces/http/refreshRoutes.ts
- JWT middleware/guards in src/core/jwt/authMiddleware.ts

Refresh token persistence (in-memory + DB schema):
- In-memory sessions repository with hashed refresh tokens and metadata (ip, userAgent, fingerprint)
- Operations: create, findByTokenHash, findAllByUserId, revokeByTokenHash, revokeAllForUser, cleanupExpired
- Migration added to extend sessions table with revoked_by and revoked_reason, plus index on (user_id, revoked_at)
- Only token hashes are stored, not raw refresh tokens
- Logout endpoints revoke single token or all tokens for a user
- A maintenance endpoint /api/auth/tasks/cleanup-expired triggers cleanup in-memory (placeholder for a cron job)
